# AWS IAM

与 Amazon Web Services（AWS）云安全相关的关键概念。这包括云安全原则，以及使用 AWS Identity and Access Management（AWS IAM）的用户、组、角色和策略来保护对云资源的访问。
    • 在确定如何将安全应用于架构时，请注意责任共担模型。

    • 使用架构良好框架（Well-Architected Framework）的安全支柱来识别设计原则。
        ◦ 实施强大的身份基础：集中管理身份，并力求消除对长期静态凭证的依赖。
        ◦ 保护传输中与静态数据：将数据按敏感度分级，并使用加密等机制。
        ◦ 在所有层面应用安全：采用纵深防御的方法，设置多种安全控制，并将其融入所有层面。
        ◦ 让人员远离数据：这可以降低管理不当或修改的风险，也能减少处理敏感信息时的人为错误。
        ◦ 保持可追溯性：实时监控和审计环境中的操作和变更，并为之创建告警。
        ◦ 为事件做好准备：执行事件响应演练，并使用带自动化的工具，以
提高检测、调查和恢复的速度。
        ◦ 自动化安全最佳实践：构建安全的架构，其中包括实施已定义且受管理的控制措施。
    • 始终应用最小权限策略：最小权限策略是一种网络安全策略，它仅授予用户、应用程序和系统执行其特定职能所严格必需的权限和访问权，绝不多授。其主要目标是缩小攻击面，并限制内部威胁、错误或攻击者窃取凭证后可能造成的潜在损害，从而使在网络中进行横向移动变得更加困难。

AWS Identity and Access Management（AWS IAM）

    • 安全地控制对 AWS 资源的个人和组访问。
    • 与其他 AWS 服务集成。
    • 支持联合身份管理。
    • 支持多重身份验证（MFA）。
    • 支持细粒度的权限。

以下术语是 IAM 特有的，你将在本课程中一直使用它们：
    • IAM 资源是存储在 IAM 中的用户、组、角色、策略或身份提供者对象。与其他的 AWS 服务一样，你可以添加、编辑和删除 IAM 资源。
    • IAM 实体是 AWS 用于身份验证的 IAM 资源对象。这些包括 IAM 用户和角色。借助 IAM 实体，可以为其提供登录控制台以及通过 API 或 AWS 命令行界面（AWS CLI）向 AWS 服务发出编程式请求的能力。
    • IAM 身份是用于标识和分组的 IAM 资源对象。你可以将策略附加到 IAM 身份。这些包括用户、组和角色。
    • 主体（Principal）是指使用 AWS 账户根用户、IAM 用户或 IAM 角色登录并向 AWS 发出请求的人员或应用程序。主体包括代入的角色和联合用户，即没有 AWS 账户的外部身份。

以下是一些用于保护访问的最佳实践：
    • 遵循最小权限原则
    • 启用 MFA：
    • 要求自然人用户通过临时凭证访问 AWS
    • 轮换访问密钥
    • 使用安全且复杂的密码
    • 保护本地凭证
    • 使用 AWS Organizations
    • 启用 AWS CloudTrail
    • 保护根用户

请求时的权限判定

面对一个请求时，会检查是否存在某个策略。
    • 如果被拒绝：显式拒绝（Denegación explícita）
    • 如果未被允许：隐式拒绝（Denegación implícita）
默认情况下，一切都是被拒绝的。需要获得权限才能验证该请求。

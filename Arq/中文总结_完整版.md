## 一、AWS 云架构：存储

### 1. 三种存储层级

| 层级 | 特点 | 代表服务 |
|------|------|----------|
| **块级存储** | HDD/SSD，划分为块 | Amazon EBS |
| **文件级存储** | 数据作为文件夹中的单个信息项 | Amazon EFS、FSx |
| **对象级存储** | 结构化对象（数据+元数据+唯一标识符），无限存储、全局访问 | Amazon S3 |

### 2. 块存储（EBS）卷类型

- **通用型 SSD**：gp2（通用/低成本）、gp3（一致性能、成本更低）
- **预置 IOPS SSD**：io1/io2（高 IOPS、低延迟）、io2 Block Express（AWS 最高性能、最低延迟）
- **吞吐量优化 HDD**：st1（顺序、高吞吐，如大数据、日志分析）
- **冷 HDD**：sc1（顺序但低性能、稳定、最便宜）

### 3. 文件存储

- **AWS EFS**：基于 Linux、可共享、可扩展、可配置、与 AWS 服务集成。
- **AWS FSx**：Windows File Server（基于 Windows）、Lustre（处理并生成大量数据）、ONTAP、OpenZFS。

### 4. 对象存储（S3）

**核心特性**：
- 对象存储；数据 + 元数据 + 全局唯一标识符。
- 无限存储、全局访问。
- 在 **3 个可用区（AZ）** 中冗余。
- AWS 中 **访问灵活性最高** 的服务（多种认证方式）。
- 支持 **生命周期策略**，自动在不同存储层之间移动数据以优化成本。
- 支持 **版本控制** 与 **对象锁定**，防止意外删除。
- 可与 **KMS** 集成，对静态与传输中数据进行加密。
- 与其他 AWS 服务高度集成，是云架构的中央存储。
- 是唯一能与其余服务交互的服务。

**S3 存储类（从热到冷）**：
- Standard（频繁访问）
- Intelligent-Tiering（自动成本优化）
- Standard-IA（不频繁访问，需即时访问）
- One Zone-IA（单区、低成本、非关键）
- Glacier Instant Retrieval（毫秒级归档）
- Glacier Flexible Retrieval（分钟到小时级归档）
- Glacier Deep Archive（极低成本长期归档）
- S3 Express One Zone（最低延迟、最高性能）

**S3 属性**：文件必须放入存储桶；标识符全局唯一；**文件最大 5 TB**。

**访问方式**：控制台、CLI、SDK、REST API。

### 5. 数据分类

结构化 / 非结构化 / 半结构化。

### 6. 迁移与备份服务

- **迁移**：
  - Datasync：自动化本地与 AWS 之间的数据迁移。
  - Snow 系列：Snowcone（小巧便携）、Snowball（PB 级）、Snowmobile（EB 级、安全卡车）。
- **备份与复制**：
  - AWS Backup：集中化、自动化的托管备份服务。
  - EBS Snapshots：EBS 卷的时间点备份到 S3。
  - S3 Replication：同区域或跨区域自动复制对象。

## 二、AWS 云架构：管理

### 交互方式
AWS 控制台（Web）、AWS CLI（命令行）、AWS SDK（集成包）、REST API（API 调用）。

### 三种管理类型对比

| 类型 | 定义 | 用户控制范围 | 调配与部署 |
|------|------|--------------|------------|
| **自管理 Self-managed** | 用户负责服务器与操作系统 | 高（CPU、内存、网络、IAM、启动、OS、补丁） | 需用户调配，部署需等待 |
| **完全托管 Fully managed** | 供应商负责 OS 与硬件 | 中（CPU、内存、网络、IAM、启动） | 供应商配置，等待较短 |
| **无服务器 Serverless** | 无需调配/配置/管理 | 无（仅网络策略、IAM、启动） | 开箱即用 |

> 核心权衡：**控制力越强，管理负担越重；托管程度越高，部署越快捷。**

## 三、AWS IAM：身份与访问管理

### 1. 云安全设计原则（架构良好框架的安全支柱）

- **强大身份基础**：集中管理身份，消除长期静态凭证依赖。
- **保护数据**：按敏感度分级，传输中与静态数据均加密。
- **纵深防御**：在所有层面应用多层安全控制。
- **让人员远离数据**：降低误操作与人为错误风险。
- **可追溯性**：实时监控、审计并告警。
- **为事件做准备**：响应演练 + 工具自动化。
- **自动化最佳实践**：构建包含受控措施的安全架构。
- **最小权限原则**：只授予严格必需的权限，缩小攻击面、限制横向移动。

### 2. IAM 四大核心术语

| 术语 | 含义 |
|------|------|
| **IAM 资源** | 存于 IAM 的用户、组、角色、策略或身份提供者对象 |
| **IAM 实体** | 用于身份验证的对象（用户、角色） |
| **IAM 身份** | 用于标识和分组的对象（用户、组、角色），可附加策略 |
| **主体 Principal** | 使用根用户/IAM 用户/角色发起请求的人员或应用 |

### 3. 访问保护最佳实践

- 遵循最小权限原则
- 启用 MFA
- 使用临时凭证而非长期凭证
- 轮换访问密钥
- 使用强复杂密码
- 保护本地凭证
- 使用 AWS Organizations
- 启用 AWS CloudTrail
- 保护根用户

### 4. 权限判定机制

- **默认拒绝**：一切都默认被拒绝，需显式授权才可执行。
- 检查策略时：
  - **显式拒绝**：存在拒绝策略 $\rightarrow$ 拒绝。
  - **隐式拒绝**：未明确允许 $\rightarrow$ 拒绝。

> 关键结论：**除非被明确允许，否则请求一律被拒绝。**

## 四、要点速记

1. 存储三大层级：块、文件、对象，各有适用场景。
2. S3 是 AWS 的中央存储，支持生命周期策略、版本控制、加密与自动分层。
3. 管理方式决定控制力与运维负担的平衡。
4. IAM 安全核心：最小权限、MFA、临时凭证、可追溯。
5. 权限模型本质：**默认全部拒绝，需显式授权。**
